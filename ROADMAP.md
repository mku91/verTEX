# ROADMAP: текстуры и развёртка

План текстурирования в verTEX. Редактор делает low-poly модели в стиле PSX и
Minecraft, поэтому всё подчинено пиксель-арту. Работа идёт в ветке `textures`.

## Главный принцип

**Развёртка строится из геометрии, один раз.** У проекта есть одно число,
плотность пикселей (пикселей на единицу длины, по умолчанию 16). Когда объект
кладётся на атлас, каждая его грань ложится на текстуру так, как она есть в
пространстве, в этом масштабе: без растяжения и без скоса. В этот момент
пиксель одного размера на всех гранях, и сетка прямая.

**Дальше развёртка принадлежит автору.** Программа её больше не меняет:

- Правка геометрии не трогает места граней на атласе. Если грань после этого
  растянулась, её картинка растянется вместе с ней. Это на совести автора.
- В редакторе UV лоскут можно переставить, повернуть, отразить, а при открытом
  замке формы подвинуть его углы по пикселям.
- Место получают только новые грани, которых раньше не было: боковины после
  экструда, вторая половина зеркала.
- «Перегенерировать» раскладывает выбранные грани заново, снова без
  растяжения, и стирает нарисованное для них.

Так было не сразу. Сначала развёртка выправлялась после каждой правки модели
и гарантировала одинаковый пиксель всегда. От этого отказались по решению
автора: предсказуемость важнее.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Плотность пикселей | Одна на проект |
| Текстур | Один атлас на проект. Выбирается при создании проекта вместе с плотностью; вариант «несколько атласов» там показан как будущий |
| Что попадает в атлас | Только то, что положил пользователь: кнопка «Создать атлас» / «Добавить в атлас» в редакторе UV. Новый объект сам в атлас не попадает |
| Рисование | Только во внешней программе (Aseprite и подобные). В редакторе не рисуем |
| Как видеть грани при рисовании | Шаблон: новая область атласа заливается своим цветом с контуром каждой грани. Плюс файл-подсказка: одни контуры на прозрачном фоне, чтобы положить слоем поверх |
| Наклонные грани | Честная плотность, пиксели режутся краем грани. Одинаковый пиксель важнее целых пикселей по краю |
| Фильтрация | Только nearest, без мипмапов |
| Прозрачность | Вырезание по порогу: прозрачный пиксель это дырка |
| Защита от протекания | Вокруг каждого лоскута зарезервировано место под кайму в один пиксель. Сама кайма в рабочей картинке не рисуется: её добавляет экспорт, и только если попросить |
| Повторяющиеся текстуры (тайлы) | Отложены, см. этап 5 |
| Что хранится | Место каждого угла грани на атласе, в пикселях. Разрез, экструд и прочее переносят эти данные |
| Картинка и отмена | Картинка атласа входит в историю отмены. Правка извне это отдельный шаг |

## Чего не будет

- Свободного перетаскивания UV с растяжением.
- Автоматических развёрток с искажениями.
- PBR, карт нормалей, групп сглаживания.
- Мипмапов и сглаживающей фильтрации.
- Инструментов выравнивания плотности: она одинакова всегда.
- Рисования внутри редактора.

## Как это устроено

- **Лоскут** это грани одного объекта, лежащие в одной плоскости и связанные
  рёбрами. Он раскладывается по осям своей плоскости: сетка на нём стоит
  «прямо» в собственных осях объекта.
- **Место лоскута** на атласе не меняется само. Картинка остаётся на грани
  при любой правке модели.
- **Разрез** даёт новым вершинам места между концами разрезанного ребра,
  картинка на кусках остаётся где была.
- **Копия объекта** смотрит на ту же картинку, что и оригинал, пока её не
  перегенерировать.
- Когда места нет, **атлас удваивается** по короткой стороне. Нарисованное
  остаётся на месте.
- Файл проекта `house.vertex` один и содержит текстуру внутри себя. Для
  внешнего редактора картинка дополнительно выкладывается рабочей копией во
  временную папку системы: `house.atlas.png` и подсказка с контурами
  `house.atlas.guide.png`. За картинкой следит программа: сохранённое во
  внешнем редакторе сразу видно на модели.
- Временные папки не копятся: при запуске программа удаляет те, чей проект
  исчез, чья картинка не новее файла проекта, или которые месяц не трогали.

Код: `unwrap.js` (развёртка и упаковка), `atlas.js` (картинка, шаблон,
подсказка), `uv-editor.js` (редактор UV), `atlas-link.js` и `src/main/atlas-file.js` (рабочая копия на диске).

## Сделано

### Этап 0. Данные грани

Грань несёт места своих углов на атласе и не теряет их при разрезе, экструде,
слиянии вершин, удалении, инверсии, зеркале, копировании, отмене и сохранении.

### Этап 1. Плотность пикселей

Параметр проекта, поле в панели «Текстура». Смена плотности перестраивает
развёртку целиком. Неплоские грани попадают в список ошибок в строке состояния.

### Этап 2. Атлас

Один атлас на проект, хранится в файле проекта (`textures/atlas.png`). Режим
отображения «Текстура». Связь с внешним редактором через файл рядом с
проектом, файл-подсказка с контурами. Формат проекта версии 3.

### Этап 3. Автоматическая развёртка

Объект, положенный на атлас, получает развёртку без дальнейших действий. Упаковка с каймой
вокруг каждого лоскута, рост атласа, перенос картинки при переезде лоскута, шаблон для
новых областей. Кнопка полной переупаковки.

### Этап 4. Редактор UV, первая часть

Панель внизу вместо трёх видов (кнопка на левой панели, клавиша U): атлас с
контурами граней, масштаб колесом, сдвиг вида правой кнопкой.

- Клик выбирает лоскут, его грани выделяются и в сцене.
- Лоскут перетаскивается на другое место картинки по целым пикселям. Рядом с
  чужим лоскутом он встаёт точно на него: так несколько граней получают одну
  картинку.
- Поворот на 90° в обе стороны, отражение по горизонтали и вертикали.
- Лоскут, поставленный руками, закреплён: автоматическая раскладка его не
  двигает.
- «Перегенерировать»: выбранные лоскуты делаются заново. Нарисованное для них
  стирается, закрепление и изменённая форма снимаются, лоскуты раскладываются
  и заливаются шаблоном. Без выделения перегенерируется весь атлас.
- Замок формы: открыт, значит у выбранных лоскутов маркеры в углах, их можно
  двигать по целым пикселям. Лоскут с изменённой формой обведён оранжевым.
- Перестановка меняет только привязку грани к картинке. Сами пиксели не
  двигаются, прежнее место остаётся как было.

## Дальше

### Этап 4. Редактор UV, оставшееся

- Сшить по ребру: соседняя грань разворачивается через общее ребро, рисунок
  идёт через него без шва. Разрезать шов: обратная операция.
- Выбор отдельной грани внутри лоскута, а не только лоскута целиком.
- Сдвиг стрелками, выделение рамкой.
- Команда «дублировать объект с общей текстурой»: сейчас копия объекта получает
  собственное место на атласе с копией картинки.

### Этап 5. Повторяющиеся текстуры (тайлы)

Отложено по решению. Грани показывают повторяющийся участок текстуры, соседние
грани стыкуются без шва. Потребует решить, живёт ли тайл в общем атласе или в
отдельной текстуре: движки не умеют повторять кусок атласа.

### Этап 6. Экспорт

- glTF (.glb) с текстурой, иерархией объектов и их поворотами.
- OBJ с MTL.
- Кайма против протекания как необязательная настройка экспорта: повторить
  крайние пиксели каждого лоскута наружу. Место под один пиксель уже
  зарезервировано раскладкой, готовая функция есть в `atlas.js`. Для
  уменьшенных копий текстуры в движке нужна кайма шире, это потребует
  перекладки с большим отступом.
- Памятка по настройкам импорта для Godot, Unity и Blender.

### Этап 7. Предпросмотр в стиле PSX (необязательный)

Дрожание вершин, аффинное искажение текстур, понижение глубины цвета,
вершинные цвета как дешёвое освещение. Только режимы просмотра.

## Мелкие долги по сделанным этапам

- **Зеркало.** Зеркальная половина сейчас получает своё место на атласе. Нужно
  дать ей те же пиксели с отражением: это вдвое экономит текстуру.
- **Вершины вне пиксельной сетки.** Нет предупреждения и подсветки.
- **Шаг сетки в пикселях.** Сетка привязки совпадает с пикселями при
  плотности, равной степени двойки, но нигде не подписана в пикселях.
- **Переупаковка без потерь.** Полная переупаковка сейчас стирает нарисованное.
  Можно переносить картинки лоскутов на новые места.
- **Настройки вида.** Освещённая или неосвещённая модель, двусторонность.

## Несколько атласов (на будущее)

Заложено: у объекта хранится идентификатор атласа, на котором он лежит, а не
просто флаг. Окно нового проекта уже содержит выбор режима. Чтобы сделать:
список атласов в проекте, выбор атласа при добавлении объекта, своя плотность
и свой файл у каждого, материал на каждый атлас при отрисовке и экспорте.

## Открытые вопросы

1. Несколько текстур или материалов на проект: понадобятся ли, и для чего.
2. Формат экспорта в первую очередь: glTF или сразу FBX.
