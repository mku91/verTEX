# ROADMAP: текстуры и развёртка

План текстурирования в verTEX. Редактор делает low-poly модели в стиле PSX и
Minecraft, поэтому всё подчинено пиксель-арту. Работа идёт в ветке `textures`.

## Главный принцип

**Развёртка не рисуется руками, а выводится из геометрии.** У проекта есть одно
число, плотность пикселей (пикселей на единицу длины, по умолчанию 16). Каждая
грань ложится на текстуру так, как она есть в пространстве, в этом масштабе.
Её можно только сдвинуть на целые пиксели, повернуть на 90° или отразить.

Поэтому два требования выполняются по построению, а не проверкой:

- **Размер пикселя одинаков на всей модели.** Масштаб у всех граней один.
- **Сетка всегда прямая.** Скос и неравномерное растяжение нечем задать.

## Принятые решения

| Вопрос | Решение |
|---|---|
| Плотность пикселей | Одна на проект |
| Текстур | Один атлас на проект. Несколько текстур и материалов рассмотрим позже |
| Рисование | Только во внешней программе (Aseprite и подобные). В редакторе не рисуем |
| Как видеть грани при рисовании | Шаблон: новая область атласа заливается своим цветом с контуром каждой грани. Плюс файл-подсказка: одни контуры на прозрачном фоне, чтобы положить слоем поверх |
| Наклонные грани | Честная плотность, пиксели режутся краем грани. Одинаковый пиксель важнее целых пикселей по краю |
| Фильтрация | Только nearest, без мипмапов |
| Прозрачность | Вырезание по порогу: прозрачный пиксель это дырка |
| Защита от протекания | У каждого лоскута кайма в один пиксель, в ней повторены его крайние пиксели. Кайма пересчитывается сама, рисовать в ней нельзя |
| Повторяющиеся текстуры (тайлы) | Отложены, см. этап 5 |
| Что хранится | Место каждого угла грани на атласе, в пикселях. Разрез, экструд и прочее переносят эти данные |
| Картинка и отмена | Картинка атласа входит в историю отмены. Правка извне это отдельный шаг |

## Чего не будет

- Свободного перетаскивания UV с растяжением.
- Автоматических развёрток с искажениями.
- PBR, карт нормалей, групп сглаживания.
- Мипмапов и сглаживающей фильтрации.
- Инструментов выравнивания плотности: она одинакова всегда.
- Рисования внутри редактора.

## Как это устроено

- **Лоскут** это грани одного объекта, лежащие в одной плоскости и связанные
  рёбрами. Он раскладывается по осям своей плоскости: сетка на нём стоит
  «прямо» в собственных осях объекта.
- **Место лоскута** на атласе сохраняется, пока лоскут в него помещается.
  Картинка остаётся на грани при перемещении, повороте, разрезе, экструде.
- Лоскут, который вырос и не помещается, **переезжает вместе с картинкой**.
  Освободившееся место очищается.
- Когда места нет, **атлас удваивается** по короткой стороне. Нарисованное
  остаётся на месте.
- Рядом с файлом проекта `house.vertex` лежат `house.atlas.png` (сама картинка)
  и `house.atlas.guide.png` (контуры граней). За картинкой следит программа:
  сохранённое во внешнем редакторе сразу видно на модели.

Код: `unwrap.js` (развёртка и упаковка), `atlas.js` (картинка, шаблон,
подсказка), `atlas-link.js` и `src/main/atlas-file.js` (файл рядом с проектом).

## Сделано

### Этап 0. Данные грани

Грань несёт места своих углов на атласе и не теряет их при разрезе, экструде,
слиянии вершин, удалении, инверсии, зеркале, копировании, отмене и сохранении.

### Этап 1. Плотность пикселей

Параметр проекта, поле в панели «Текстура». Смена плотности перестраивает
развёртку целиком. Неплоские грани попадают в список ошибок в строке состояния.

### Этап 2. Атлас

Один атлас на проект, хранится в файле проекта (`textures/atlas.png`). Режим
отображения «Текстура». Связь с внешним редактором через файл рядом с
проектом, файл-подсказка с контурами. Формат проекта версии 3.

### Этап 3. Автоматическая развёртка

Любая модель получает развёртку без действий пользователя. Упаковка с каймой
вокруг каждого лоскута, рост атласа, перенос картинки при переезде лоскута, шаблон для
новых областей. Кнопка полной переупаковки.

## Дальше

### Этап 4. Окно развёртки

- 2D-вид атласа с контурами граней внутри редактора.
- Выделение грани в 3D подсвечивает её на атласе и наоборот.
- Операции над лоскутом: сдвиг по целым пикселям, поворот на 90°, отражение.
- Сшить по ребру: соседняя грань разворачивается через общее ребро, рисунок
  идёт через него без шва. Разрезать шов: обратная операция.

Готово, когда: развёртку куба можно собрать в крест.

### Этап 5. Повторяющиеся текстуры (тайлы)

Отложено по решению. Грани показывают повторяющийся участок текстуры, соседние
грани стыкуются без шва. Потребует решить, живёт ли тайл в общем атласе или в
отдельной текстуре: движки не умеют повторять кусок атласа.

### Этап 6. Экспорт

- glTF (.glb) с текстурой, иерархией объектов и их поворотами.
- OBJ с MTL.
- Ширина каймы как настройка экспорта: одного пикселя хватает для сглаживания,
  для уменьшенных копий текстуры в движке нужно больше.
- Памятка по настройкам импорта для Godot, Unity и Blender.

### Этап 7. Предпросмотр в стиле PSX (необязательный)

Дрожание вершин, аффинное искажение текстур, понижение глубины цвета,
вершинные цвета как дешёвое освещение. Только режимы просмотра.

## Мелкие долги по сделанным этапам

- **Зеркало.** Зеркальная половина сейчас получает своё место на атласе. Нужно
  дать ей те же пиксели с отражением: это вдвое экономит текстуру.
- **Развёртка во время перетаскивания.** Пока тянешь вершину, текстура на
  грани тянется и выправляется при отпускании. Нужно выправлять на лету.
- **Вершины вне пиксельной сетки.** Нет предупреждения и подсветки.
- **Шаг сетки в пикселях.** Сетка привязки совпадает с пикселями при
  плотности, равной степени двойки, но нигде не подписана в пикселях.
- **Переупаковка без потерь.** Полная переупаковка сейчас стирает нарисованное.
  Можно переносить картинки лоскутов на новые места.
- **Настройки вида.** Освещённая или неосвещённая модель, двусторонность.

## Открытые вопросы

1. Несколько текстур или материалов на проект: понадобятся ли, и для чего.
2. Формат экспорта в первую очередь: glTF или сразу FBX.
